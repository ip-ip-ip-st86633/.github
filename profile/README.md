<p>带宽上限不是一个固定数字，它由出口线路、并发数、中转链路共同决定。本文先讲上限的来源，再给常见档位，然后解释为什么跑不满，最后对比机房代理并说明测速方法和选带宽的思路。</p>
<h2>一、带宽上限到底由谁决定</h2>
<p>住宅代理的带宽来自真实家庭宽带，出口那一段通常是 100M 到 1000M 的下行、30M 到 100M 的上行，这才是硬天花板。</p>
<p>你买到的额度只是服务商的分配值，可能按并发线程限，也可能按流量限。分配值超过出口物理带宽时，写多少都跑不上去。</p>
<p>中间还有一层中转。请求先到网关再到住宅节点，这段链路如果拥塞，你测到的速度反映的是中转质量，不是住宅线路质量。</p>

<h2>三、为什么实际速度跑不满</h2>
<p>第一个原因是并发分摊。一条 100M 出口分给十个客户，单个客户不可能拿到 100M，宣传页上的数字是整条线的能力。</p>
<p>第二个原因是上行瓶颈。家庭宽带上行普遍偏小，做上传、推流、同步时先撞上行，下行再宽也没用。</p>
<p>第三个原因是协议开销和加密。代理隧道封装、TLS 握手、跨境绕行都会吃掉一部分有效带宽，长连接比短连接表现好些。</p>
<h3>延迟和带宽是两件事</h3>
<p>带宽决定一次能搬多少数据，延迟决定来回一趟要多久。小请求密集的业务，延迟的影响往往比带宽更大。</p>
<h2>四、和机房代理比谁更快</h2>
<p>同样条件下机房代理更快。机房接入多线 BGP，路由路径短，延迟常在十几毫秒；住宅线路绕行多，延迟普遍高出一截。</p>
<p>带宽也更稳。机房是对称带宽，上行下行一样；家庭宽带上下行不对称，突发流量容易排队。</p>
<p>但快不等于合用。机房段在地址库里标为数据中心，很多业务场景认的是归属类型而不是速度，这时候快反而没意义。</p>

<h2>五、怎么测出真实速度</h2>
<p>别用单个大文件测一次就下结论。用固定大小的多线程下载跑十分钟，记录平均值和波动区间，看的是持续性而不是峰值。</p>
<p>再测一组小请求，看每秒完成数和首字节时间。很多业务慢在小请求排队，而不是总带宽不够。</p>
<p>测试要在你的真实办公网络里做，用同一台机器、同一时段对比不同供应商。跨时段测出来的差异常常是本地网络造成的。</p>
<h3>记录要能复现</h3>
<p>把时间、节点、线程数、平均速度、失败率写在一张表里，下次换套餐或换供应商直接对照，避免凭感觉判断。</p>
<h2>六、按业务配多少带宽</h2>
<p>后台类操作以页面和小文件为主，每个账号 2M 到 5M 就够，配多了是浪费。重点是延迟低、连接稳。</p>
<p>采集类看并发，每个线程 1M 上下即可，瓶颈通常在目标站点的限流，而不是你的带宽。</p>
<p>上传、直播、大文件同步才需要高档位带宽，这种场景优先看上行和是否独享，别只盯着下行数字。</p>
<h3>留一点余量</h3>
<p>按峰值需求加三成配置比较稳妥，线路抖动时不至于排队。余量给太多会推高成本，按实际峰值算就行。</p>
<h2>常见问答</h2>
<h3>住宅代理的带宽有硬性上限吗？</h3>
<p>答：有，出口家庭线路的物理带宽就是上限。国内家庭宽带上行常见 30M 到 50M，海外部分线路可到 100M 以上，再高的标称值要核实。</p>
<h3>为什么标称 100M 实测只有十几兆？</h3>
<p>答：多半是并发分摊或上行瓶颈。同一条出口分给多个用户，单用户拿不到全额；上传场景先撞上行，下行再宽也提不上去。</p>
<h3>机房代理快多少？</h3>
<p>答：延迟通常低一半以上，带宽也更容易跑满，因为是对称线路加短路由。具体倍数取决于两端位置，没有统一数值。</p>
<h3>带宽买大一点是不是更稳？</h3>
<p>答：不一定。稳定性更多取决于出口线路质量和并发密度，带宽只解决吞吐。并发挤在一起时，加带宽的收益有限。</p>
